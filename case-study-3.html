Case Study 03

Inventory Monitoring & Reorder Workflow

Designed an automated inventory workflow that monitors new orders, locates the corresponding inventory record, updates stock quantities, evaluates low-inventory conditions, and triggers automated notifications when follow-up is required.

Project Overview

Inventory monitoring can become time-consuming when employees must repeatedly review spreadsheets, calculate updated quantities, and manually identify items that require attention.

This project demonstrates how an automated workflow can monitor new order activity, find the appropriate inventory record, update the remaining quantity, evaluate business rules, and trigger a secondary notification workflow when inventory reaches a defined condition.

Challenge

Reduce repetitive inventory monitoring while improving the consistency of stock updates and low-inventory identification.

Solution

Build a connected Make.com workflow that monitors orders, searches inventory records, updates quantities, and triggers notifications based on defined conditions.

Outcome

Created a repeatable process that improves inventory visibility, reduces manual review, and supports faster response to stock conditions requiring attention.

Project Visual

The workflow below shows how new order data is monitored, inventory quantities are located and updated, and low-inventory conditions trigger a secondary notification workflow.

How the Automation Works

  1. Google Sheets monitors for new order records.
  2. When a new order is detected, the workflow searches the inventory data to locate the matching item and current quantity.
  3. A variable is created to calculate or prepare the updated inventory quantity.
  4. The corresponding Google Sheets inventory record is updated with the new quantity.
  5. The updated inventory level is evaluated against a defined low-inventory condition.
  6. When the condition is met, an HTTP request triggers a secondary workflow.
  7. A webhook receives the request and starts the notification process.
  8. Gmail sends an automated message so the appropriate person can review the inventory condition and take the next action.

Business Rules & Exception Handling

The workflow is designed around operational rules rather than simply moving information between applications.

  • A new order must be detected before inventory processing begins.
  • The workflow must locate the correct inventory record before changing the quantity.
  • Inventory quantities are updated using the order information captured by the workflow.
  • The notification workflow is triggered only when inventory meets the defined low-stock condition.
  • The notification process is separated from the primary inventory workflow through HTTP and webhook connections.

Separating the primary inventory process from the notification process creates a more modular design and makes future changes easier to manage.

Tools & Methods

Make.com Google Sheets Variables Filters HTTP Webhooks Gmail Business Rules Workflow Design Automation Testing

Challenges & Problem Solving

One of the key challenges was ensuring that each new order updated the correct inventory record before any low-inventory condition was evaluated.

Testing needed to cover multiple scenarios, including different order quantities, normal stock levels, low-stock conditions, and the connection between the primary inventory workflow and the secondary notification workflow.

The workflow was also structured so that notification logic could be changed or expanded independently from the primary inventory process. This creates a more flexible foundation for future automation.

Business Value

  • Reduces repetitive manual inventory monitoring.
  • Improves the consistency of inventory quantity updates.
  • Identifies low-inventory conditions more quickly.
  • Applies inventory business rules consistently.
  • Improves visibility into inventory conditions requiring attention.
  • Reduces reliance on employees to manually identify stock issues.
  • Creates a modular workflow that can support additional alerts, rules, or integrations.
