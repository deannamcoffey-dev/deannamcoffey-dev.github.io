CASE STUDY 03

Inventory Monitoring & Reorder Workflow

Built an automated inventory workflow that updates stock levels, identifies reorder conditions, and routes notifications through a parent/child automation design.

Project Overview

Inventory management often requires repeated monitoring of stock levels and manual follow-up when products reach reorder points.

This project demonstrates how automation can monitor inventory data, evaluate reorder conditions, and trigger the appropriate workflow when stock levels require attention.

Challenge

Reduce manual inventory monitoring and make reorder decisions easier to identify.

Solution

Use automated workflows to update inventory data, evaluate conditions, and trigger notifications.

Approach

Separate workflow responsibilities using a parent/child automation structure.

Tools & Methods

Make.com Webhooks HTTP Google Sheets Gmail Workflow Design Business Rules Automation Testing

How the Workflow Works

  • Inventory information is received or updated through the automated workflow.
  • Stock levels are recorded and evaluated against defined reorder conditions.
  • The workflow determines whether additional action is required.
  • Parent and child automation scenarios separate processing responsibilities.
  • Notifications are routed when inventory reaches a condition requiring attention.
  • Google Sheets provides a structured location for inventory data.

Challenges & Problem Solving

One of the key design considerations was separating the workflow into logical components rather than placing every action inside a single automation.

A parent/child structure made it easier to organize the workflow, route information between steps, and keep individual automation responsibilities more manageable.

Testing also required checking that inventory conditions produced the correct response and that notifications were triggered only when the defined business rules were met.

Business Value

  • Reduced repetitive inventory monitoring.
  • Improved visibility into stock levels requiring attention.
  • Created a repeatable process for identifying reorder conditions.
  • Automated notification routing based on business rules.
  • Demonstrated a scalable parent/child workflow design.
